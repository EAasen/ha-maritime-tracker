# v1.2.2 Activation Error - Complete Resolution Guide

## 📋 TL;DR (Too Long; Didn't Read)

**Problem:** `TypeError: async_register_command() got an unexpected keyword argument 'allow_user_context'`

**Cause:** Your Home Assistant has stale Python cache. The code is correct but HA is loading old bytecode.

**Solution:** Delete integration → Clear cache → Reinstall (5 minutes)

---

## ✅ Verification: Code IS Correct

I've verified the current codebase:

```
✅ No deprecated hass.components patterns found
✅ No allow_user_context parameter found
✅ Correct imports are present
```

**The problem is NOT in the code—it's in your Home Assistant installation's Python cache.**

## 🚀 Quick Fix Steps

### Step 1: Remove Integration
1. Settings → Devices & Services
2. Find "Norwegian Maritime Tracker"  
3. Click ⋮ (three dots) → Delete Entry → Confirm

### Step 2: Clear Cache
SSH to your Home Assistant:
```bash
ssh root@<your-ha-ip>
cd /config/custom_components/
rm -rf marinetraffic_tracker/
find /config -type d -name __pycache__ -exec rm -rf {} + 2>/dev/null
find /config -type d -name .pytest_cache -exec rm -rf {} + 2>/dev/null
exit
```

### Step 3: Reinstall
HACS → Integrations → Custom repositories → Add:
- URL: `https://github.com/EAasen/ha-maritime-tracker`
- Category: `Integration`
- Install v1.2.2

### Step 4: Restart
Settings → System → Restart Home Assistant

### Step 5: Reconfigure
Settings → Devices & Services → + Create Automation → Norwegian Maritime Tracker

## 🔍 What Actually Changed in v1.2.2

### The Core Issue
Home Assistant 2026.10.4 removed the `allow_user_context` parameter from WebSocket API. The old code broke because it tried to use this unsupported parameter.

### The Fix
**Before (broken):**
```python
hass.components.websocket_api.async_register_command(
    cmd, handler, allow_user_context=False)
```

**After (fixed):**
```python
websocket_api.async_register_command(hass, cmd, handler)
```

**Why it works:**
- Uses modern import pattern
- Passes `hass` as first parameter (required)
- No unsupported parameters

---

## ✨ Why This Error Happens

### Python Import Caching (The Root Cause)

```
Timeline of Events:
1. You had v1.2.1 installed → Home Assistant compiled it to .pyc
2. Upgraded to v1.2.2 → New code is correct
3. Home Assistant starts up → Python loads .pyc cache instead of new code
4. Old code runs → Tries to use allow_user_context parameter
5. Error! → Home Assistant 2026.10.4 rejects unsupported parameter
```

### The Solution is Simple
```
Clear the cache → Python compiles new code to fresh .pyc → New code runs → Success!
```
