# v1.2.5 - Location Selection Validation Fix

## Problem

When users submitted their location selection after choosing a point on the map, they received:

```
Unknown error occurred
- not a valid option at 'location'
```

This error prevented users from completing the setup flow despite successfully:
1. Seeing the map display ✅ (v1.2.4 fix)
2. Interacting with the map ✅
3. Clicking submit ❌ (blocked here)

---

## Root Cause Analysis

### The Issue
The location schema included `extra=vol.PREVENT_EXTRA`, which told voluptuous to reject ANY fields that weren't explicitly defined in the schema.

**Original Code:**
```python
return vol.Schema(
    {
        vol.Required(_CONF_LOCATION): selector.LocationSelector(...),
    },
    extra=vol.PREVENT_EXTRA,  # ❌ BLOCKS LocationSelector's dict!
)
```

### Why This Failed
Home Assistant's `LocationSelector` returns a dictionary like:
```python
{
    "latitude": 58.5,
    "longitude": 5.75,
    "radius": 2500.0,
    # potentially other fields...
}
```

But `extra=vol.PREVENT_EXTRA` says: **"Only allow exactly 'location' field, reject everything inside it!"**

When voluptuous tried to validate the submitted location dict, it couldn't validate fields inside the dict because:
- LocationSelector itself handles validation of its returned value
- But `PREVENT_EXTRA` was preventing that internal validation from working
- Result: "not a valid option at 'location'" (schema rejection)

---

## Solution

### The Fix
Removed the `extra=vol.PREVENT_EXTRA` constraint:

**Fixed Code:**
```python
return vol.Schema(
    {
        vol.Required(_CONF_LOCATION): selector.LocationSelector(...),
    },
    # ✅ Removed extra=vol.PREVENT_EXTRA - allows LocationSelector to work
)
```

### Why This Works
1. **Schema Only Defines Form Structure** - The vol.Schema defines which form fields exist
2. **Selector Handles Validation** - LocationSelector handles its own validation/transformation
3. **No Extra Constraints** - Without PREVENT_EXTRA, LocationSelector's dict is accepted as-is
4. **Our Validation Still Runs** - async_step_radius() still validates the location thoroughly

### What Gets Validated
1. **By voluptuous schema**: Field presence, basic structure
2. **By LocationSelector**: Dict structure, coordinate format
3. **By async_step_radius()**: 
   - Location exists ✅
   - Has latitude/longitude ✅
   - Within Norway bounds ✅
   - Type correctness ✅
